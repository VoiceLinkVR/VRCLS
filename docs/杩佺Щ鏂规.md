这是一个非常详尽的迁移方案，旨在将现有的 Python (Flask + PyWebView) 架构完全迁移到 **C# (.NET 8/9 + WPF)**，采用 **MVVM** 架构，并确保 **1:1 还原原有功能**。带迁移的项目位置在D:\git\gitlab\VRCLS-master。

### 核心目标
1.  **性能提升**：利用 C# 的真多线程和原生音频 API (WASAPI) 消除延迟。
2.  **架构优化**：移除 Flask/SocketIO 中间层，使用内存内事件/消息传递。
3.  **完全还原**：包括本地/云端语音识别、翻译、TTS、OSC (VRChat)、SteamVR Overlay、点阵屏支持等。

### 第三部分：迁移实施步骤 (Step-by-Step)

#### 阶段一：基础建设 (Infrastructure)

1.  **创建项目**：建立上述解决方案结构。
2.  **定义模型 (Models)**：
    *   将 `defaultConfig.py` 中的 JSON 结构转换为 C# Class (`AppConfig.cs`)。使用 `[JsonPropertyName]` 属性处理命名风格差异。
3.  **配置 DI**：
    在 `App.xaml.cs` 中配置 `ServiceCollection`，注册 `MainViewModel` 和所有 Service 为 `Singleton` 或 `Transient`。

#### 阶段二：音频核心流水线 (The Core Pipeline) - 最关键！

这是性能优化的核心。不再使用 Queue 跨进程，而是使用 `System.Threading.Channels` 进行内存内流式传输。

**核心逻辑实现思路：**

1.  **AudioCaptureService**: 使用 `WasapiLoopbackCapture` (桌面) 和 `WaveInEvent` (麦克风)。
    *   *改进点*：C# 可以直接处理 buffer，无需像 Python 那样频繁在 Bytes 和 Numpy Array 之间转换。
2.  **VadService**: 加载 `silero_vad.onnx`。
    *   将音频流切分为 512 采样点的帧，送入 ONNX 推理。
    *   状态机逻辑（SpeechStart, SpeechEnd）直接移植 Python 代码。
3.  **AsrService (Sherpa)**:
    *   初始化 `SherpaOnnx.OnlineRecognizer`。
    *   当 VAD 激活时，将 PCM 数据 `AcceptWaveform` 给识别器。
    *   识别结果通过 C# 事件 `OnTranscriptionResult` 广播。

**代码片段 (Service 定义):**
```csharp
public interface IAudioPipeline
{
    void StartCapture(string deviceId, bool isLoopback);
    void StopCapture();
    event EventHandler<string> TextRecognized; // 最终文本
    event EventHandler<float> VolumeLevelChanged; // 用于UI音量条
}
```

#### 阶段三：业务逻辑迁移 (Business Logic)

将 `serverActionProcess.py` 和 `handler/` 目录下的逻辑迁移到 C# Services。

1.  **TranslationService**:
    *   实现 `ITranslator` 接口。
    *   使用 `HttpClientFactory` 管理 HTTP 请求。
    *   移植 OpenAI, Google, Baidu 等 API 调用逻辑。
2.  **OscService**:
    *   使用 `Rug.Osc`。
    *   实现 `/chatbox/input` 发送。
    *   实现 Avatar 参数控制（对应 Python 的 `Avatar.py`）。
    *   *改进点*：C# 发送 OSC 几乎零延迟。
3.  **TtsService**:
    *   集成 `EdgeTTS` (有开源 C# 库) 或调用 Azure/System.Speech。
    *   音频播放使用 `NAudio.WaveOutEvent`，不再依赖外部 ffmpeg 进程播放。

#### 阶段四：UI 重写 (WPF + MVVM)

这是工作量最大的部分，需要将 Vue 界面转换为 XAML。

1.  **主界面 (MainWindow)**:
    *   使用 **MaterialDesignInXamlToolkit** 库获得类似现有的现代 UI 风格。
    *   左侧导航栏 (NavigationRail)。
    *   右侧内容区域使用 `ContentControl` 绑定 `CurrentViewModel`。
2.  **日志与状态**:
    *   使用 `ObservableCollection<LogModel>` 绑定到 `DataGrid` 或 `ItemsControl` 替代现有的日志表格。
    *   利用 `CollectionViewSource` 实现日志过滤（按来源：Mic/Desktop）。
3.  **设置页面**:
    *   将复杂的配置表单拆分为多个 `UserControl` (如 `AudioSettingsView`, `TranslationSettingsView`).
    *   使用数据绑定 (`Binding`) 直接双向绑定到 `Config` 对象，无需手动 `saveConfig` API 调用。
4.  **透明 Overlay**:
    *   创建一个 `Window`，设置 `WindowStyle="None"`, `AllowsTransparency="True"`, `Background="Transparent"`。
    *   使用 MVVM 绑定识别结果文本，实现即时显示。

#### 阶段五：SteamVR & 特殊功能

1.  **SteamVR Overlay**:
    *   引用 `OpenVR.Net`。
    *   移植 `steamvr.py` 逻辑。C# 中可以直接将 WPF 的 `Visual` 或 `Bitmap` 转换为纹理句柄传给 OpenVR，效率远高于 Python 的 PIL 生成图片再传输。
2.  **Bitmap LED**:
    *   移植 `VRCBitmapLedHandler.py`。
    *   C# 的位操作性能极佳，处理 16x8 像素数据非常简单。

### 第四部分：迁移进度表与功能对照

为了保证“保持原有所有功能”，请对照此表开发：

| 原有功能               | 迁移策略                       | 注意事项                                         |
| :--------------------- | :----------------------------- | :----------------------------------------------- |
| **WASAPI 环路录音**    | NAudio `WasapiLoopbackCapture` | 需要处理采样率重采样 (Resampler)                 |

| **多引擎翻译**         | `HttpClient` + JSON 解析       | 建议使用策略模式 (Strategy Pattern) 管理不同引擎 |
| **TTS 播放**           | NAudio `WaveOut` + TTS API     | 需处理音频流缓冲                                 |
| **VRChat OSC**         | Rug.Osc                        | 注意处理线程安全                                 |
| **WebUI 配置页**       | WPF XAML 页面                  | 使用 MVVM 双向绑定，配置即时生效或通过保存按钮   |
| **悬浮窗 (Webview)**   | WPF 透明 Window                | 设置 `Topmost="True"`                            |
| **SteamVR 显示**       | OpenVR C# API                  | 需在独立线程运行 VR 循环以防卡顿 UI              |
| **热键控制 (V键说话)** | 全局键盘钩子 (User32.dll)      | C# 调用 Win32 API 非常方便                       |
| **日志系统**           | Serilog                        | 写入文件 + 绑定到 UI 列表                        |

### 代码示例：MVVM 架构下的主逻辑

**ViewModel (MainViewModel.cs):**

```csharp
public partial class MainViewModel : ObservableObject
{
    private readonly IAudioPipeline _audioService;
    private readonly ITranslationService _translationService;
    private readonly IOscService _oscService;

    [ObservableProperty]
    private string _recognizedText;

    [ObservableProperty]
    private string _translatedText;

    [ObservableProperty]
    private bool _isListening;

    public ObservableCollection<LogItem> Logs { get; } = new();

    public MainViewModel(IAudioPipeline audio, ITranslationService trans, IOscService osc)
    {
        _audioService = audio;
        _translationService = trans;
        _oscService = osc;

        // 订阅底层服务的事件
        _audioService.TextRecognized += OnTextRecognized;
    }

    private async void OnTextRecognized(object sender, string text)
    {
        // 回到 UI 线程 (WPF 自动处理，或使用 Dispatcher)
        RecognizedText = text;
        AddLog("Mic", text);

        // 触发翻译
        var trans = await _translationService.TranslateAsync(text, "en");
        TranslatedText = trans;

        // 发送 OSC
        _oscService.SendChatbox($"{trans} ({text})");
    }

    [RelayCommand]
    private void ToggleListening()
    {
        if (IsListening) _audioService.StopCapture();
        else _audioService.StartCapture("default", true); // true for loopback
        IsListening = !IsListening;
    }
    
    private void AddLog(string source, string text)
    {
        // 确保在 UI 线程操作集合
        Application.Current.Dispatcher.Invoke(() => {
            Logs.Insert(0, new LogItem(source, text, DateTime.Now));
        });
    }
}
```

### 总结

这个迁移方案将把 VRCLS 从一个“脚本集合”升级为一个“企业级桌面应用”。

*   **性能**：C# 对 WASAPI 和 ASIO 的支持将音频延迟降低到毫秒级。
*   **开发**：Visual Studio 强大的调试功能将结束 Python 多进程调试的噩梦。
*   **部署**：最终发布只需一个文件夹或一个单文件 EXE，无需让用户安装 WebView2 运行时或 Python 环境。

**建议开始步骤**：
先创建一个 C# 控制台程序，仅实现 `NAudio` 录音 + `SherpaOnnx` 识别，验证核心链路跑通，然后再开始画 WPF 界面。
