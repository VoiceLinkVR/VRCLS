# VRCLS 官网页面设计说明

## 1. 目标

这个站点的定位不是复杂 Web 应用，而是一个适合放在 `github.io` 上的项目介绍页。它要解决三个问题：

1. 让第一次接触 VRCLS 的用户快速理解这个项目做什么。
2. 让用户知道它和 VRChat、语音识别、翻译、OSC、TTS 的关系。
3. 给公开状态页提供清晰入口，降低用户对“服务器现在能不能用”的疑问。

## 2. 页面结构

首页采用单页式结构，导航直接定位到页面内部区块。

### 2.1 Hero 首屏

- 项目名称：`VRCLS`
- 副标题：面向 VRChat 的实时语音识别 / 翻译 / OSC 协同工具
- 操作按钮：`查看项目源码`、`查看服务状态页`
- 快速指标：`.NET 8`、`ASR / VAD`、`OSC / TTS`

设计意图：首屏先讲“价值”和“入口”，而不是一上来塞太多技术细节。

### 2.2 能力区

四张卡片：

- 实时语音链路
- 多语言翻译
- VRChat 交互控制
- 可观测性公开页

设计意图：对应用户心中的四个问题——能不能采集、能不能翻译、能不能控制、服务稳不稳定。

### 2.3 架构区

重点说明：

- 官网是静态页，适合 GitHub Pages
- 状态页前端也是静态页
- 状态数据来自后端 API
- 前后端分离，发布互不影响

设计意图：你之后升级状态 API，不需要重新改 GitHub Pages 的结构。

### 2.4 场景区

- 跨语言社交
- 主播演示 / 项目展示
- 开发者自建服务

设计意图：让页面更接近真实使用者，而不是只从开发者角度写技术文案。

### 2.5 路线图区

展示：

- 当前 Demo 已完成什么
- 真实监控接入
- 下载页 / 更新日志等后续扩展

设计意图：让站点既像官网，也像项目路线图入口。

## 3. 视觉设计

### 3.1 视觉风格

- 深色背景
- 青蓝色高亮
- 半透明面板 + 模糊玻璃感
- 卡片式布局

原因：

- 更贴近开发工具、状态页和技术产品的观感
- 与 VR、字幕、实时系统这种主题更匹配

### 3.2 响应式策略

- 桌面端使用 2~4 列卡片布局
- 平板收敛为 2 列
- 手机统一折叠为 1 列

### 3.3 技术选型

- 纯 HTML
- 纯 CSS
- 少量原生 JavaScript

原因：

- 不需要构建工具
- 最适合 GitHub Pages
- 降低维护成本

## 4. 文案来源建议

首页文案可以继续从以下内容提炼：

- `../VRCLS-CSharp/README.md`
- 原始 `VRCLS` 项目 README
- B 站教程、发布说明、下载说明
- 你的后端服务说明和爱发电说明

建议首页只放“概括”，不要把 README 原文整段照搬。
