# 迁移实施方案（结合服务器契约）

## 总体原则
- 先打通链路再做体验：配置/鉴权 → 音频/识别/翻译/OSC → UI/Overlay → 外设(TTS/SteamVR/点阵屏)。
- 以接口为中心：沿用现有接口/模型（`AppConfig`、`IAudioService`、`IRecognitionService`、`ITranslationService`），用策略模式切换本地/远端/多引擎。
- 可验证：每个里程碑要有可运行的最小示例或冒烟脚本。
- 每个阶段完成后立即 `git commit`，形成可回滚的里程碑提交。

## 分阶段计划

### 阶段 1：配置与鉴权落地
- 启动加载/退出保存 JSON 配置，移除 `MainViewModel` 中的硬编码（账号、IP、端口、语言、阈值等）。
- 鉴权适配服务器：`POST /api/login`（JSON body）获取 `access_token`，后续接口统一加 `Authorization: Bearer <token>`，处理 401/403 自动重登。
- 在 DI 中提供配置、日志、模型路径解析器，避免 ViewModel 手动 `new`。

### 阶段 2：UI/MVVM 重构（顺延至 TTS 完成后再做）
- 当前窗口设计需调整，UI 重构（MainWindow/Settings/Overlay 的 MVVM 化、状态灯/音量条、主题切换等）放在 TTS 输出与后端稳定后再处理，避免现有 UI 问题反复返工。
- 先完成后端链路（阶段 3/4/5/6），再按最新设计一并更新 UI：核心 View + ViewModel、双路监听卡片、实时日志、设备选择器、Overlay 锁定/穿透、设置页保存/实时应用等。
- 依然保持可插拔的 ViewModel 服务接口（音频、翻译、OSC 等），并预留本地 Mock 数据以便 MVP 演示。

### 阶段 3：音频与识别链路（远端 + 本地 Sherpa）
- 用工厂/DI 创建 `_micPipeline`、`_desktopPipeline`，分离实例状态。
- VAD 状态回传 UI（监听/说话/静音），实时音量条。
- 远端协议与服务器对齐：`multitranslateToOtherLanguage` 使用 multipart，字段 `sourceLanguage`/`targetLanguage`/`targetLanguage2/3`/`emojiOutput`，文件类型 `audio/opus`。
- Opus 打包遵循服务器解包：16k 单声道、20ms 帧、4 字节大端长度 + Opus 包；发送超时/重试/重连策略。
- **预留本地识别**：保留 SherpaOnnx 流水线（原 Python 本地模型），在配置中可切换“本地/远端”模式，以便离线或服务器不可达时回退；需要封装 `IRecognitionService` 的本地实现。
- 服务器特性：`sourceLanguage=zh` 走 SenseVoice HTTP；其他语言走 Whisper + 多引擎/本地翻译，支持过滤词与重复字符压缩。

### 阶段 4：翻译与文本格式化
- 实现 `ITranslationService` 策略，默认调用服务器端翻译接口（`/api/func/multitranslateToOtherLanguage`/`/api/func/webtranslate`）保证可用，再扩展 OpenAI/Google/Baidu/LibreTranslate 等第三方或本地引擎；同时调研类似 Python `translators` 的 .NET 库（如 GTranslate、DeepL.NET 等）以提供离线/回退能力。
- Chatbox 文本按 `VRCChatboxformat_new` 拼装，多语言换行，Emoji 过滤开关。

### 阶段 5：OSC 与脚本
- 完整移植 `defaultScripts`/`scripts`：命中关键词 → OSC 参数队列发送（bool/int/float，含延时）。
- 可选开启 OSC 服务器监听，转发/过滤到 UI；设置页可配置 OSC 端口/IP。

### 阶段 6：TTS 与输出
- 集成 EdgeTTS/System.Speech，翻译后播报/原文播报；可选输出到虚拟声卡；补齐 `func/tts` 代理调用（若配置）。
- CopyBox：可选自动复制最新文本。

### 阶段 7：VR/外设扩展
- SteamVR Overlay：WPF Visual → 纹理推送，尺寸/位置可配置。
- 点阵屏（VRCBitmapLed）：文本渲染与颜色控制，按原协议输出。

### 阶段 8：测试与发布
- 冒烟：VAD 分段、Opus 打包/解包一致性、`/api/login` 与 `/api/func/multitranslateToOtherLanguage` 往返、OSC 发送模拟、令牌过期/限流回退。
- 发布：模型/资源复制检查（`silero_vad.onnx`、Sherpa 模型）、配置模板生成。

## 近期优先（建议顺序）
1) 配置读写 + 鉴权接线（去硬编码，统一 Bearer Token 生命周期），UI 显示 VAD/音量状态。  
2) 远端协议敲定：Opus 打包校验、字段齐全、超时/重试/重连、错误提示。  
3) 翻译策略 + Chatbox 模板化输出（含 Emoji 过滤开关）。  
4) OSC 脚本触发与设置页；Overlay 锁定/样式。  
5) TTS/CopyBox，再推进 SteamVR/点阵屏。  

## 依赖与资源
- 服务端路径：`D:\git\gitlab\VoiceLinkServer1`。关键接口：`/api/login`、`/api/func/multitranslateToOtherLanguage`、`/api/whisper/*`、`/api/func/tts`。需要 Bearer Token。
- 音频协议：16k 单声道、20ms 帧、4 字节大端长度 + Opus 包（与服务器 `packaged_opus_stream_to_wav_bytes` 对齐）。
- 模型：`models/silero_vad.onnx` 已在仓库；Sherpa 模型需放置并配置路径。
- NuGet：如需 WS 流式另加 `Websocket.Client`；现有 `Concentus`/`NAudio`/`OnnxRuntime`/`SherpaOnnx` 已在用。

## 验证要点
- 双路监听并发稳定，停止/重启无资源泄漏。
- 远端接口：超时、限流、Token 过期的重试/提示；Opus 解包成功率。
- OSC 发送格式与 VRChat 参数匹配，Chatbox 输出不截断。
- UI/Overlay 在 DPI 缩放下布局正确，深浅色切换无样式冲突。
