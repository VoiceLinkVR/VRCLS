## 二、严重级问题 - 必须修复

### 2.1 HttpClient 滥用导致 Socket 耗尽

**问题描述：** 三个服务各自创建独立的 `HttpClient` 实例，导致连接池碎片化和 Socket 泄漏。

**涉及文件：**
- `02.VRCLS.Services/Recognition/FastApiRecognitionService.cs` 第 41-44 行
- `02.VRCLS.Services/Translation/ServerTranslationService.cs` 第 39-42 行
- `02.VRCLS.Services/Tts/ServerTtsService.cs` 第 46-49 行

**问题代码：**
```csharp
// 每个服务都这样创建 -- 反模式！
_httpClient = new HttpClient
{
    Timeout = TimeSpan.FromSeconds(30)
};
```

**影响：**
- 每个 HttpClient 维护独立的 SocketsHttpHandler 连接池（默认 10 连接/端点）
- Socket 在 Dispose 后仍保持 TIME_WAIT 状态 60+ 秒
- 高负载时可触发 `SocketException: Address already in use`
- 3 个服务 x 10 连接 = 30 个 Socket 常驻

**修复方案：引入 IHttpClientFactory**

**步骤 1：添加 NuGet 包**
```xml
<!-- 03.VRCLS.UI.csproj -->
<PackageReference Include="Microsoft.Extensions.Http" Version="10.0.0" />
```

**步骤 2：在 DI 容器注册**
```csharp
// App.xaml.cs ConfigureServices()
services.AddHttpClient("VRCLSApi", client =>
{
    client.BaseAddress = new Uri(BackendUrlHelper.BuildApiBaseUrl(_config));
    client.Timeout = TimeSpan.FromSeconds(30);
    client.DefaultRequestHeaders.ConnectionClose = false;
})
.ConfigurePrimaryHttpMessageHandler(() => new SocketsHttpHandler
{
    AutomaticDecompression = DecompressionMethods.GZip | DecompressionMethods.Deflate,
    MaxConnectionsPerServer = 5,
    PooledConnectionLifetime = TimeSpan.FromMinutes(5),
});
```

**步骤 3：改造服务构造函数**
```csharp
// FastApiRecognitionService.cs
public FastApiRecognitionService(
    AppConfig config,
    string pipelineName,
    IBackendAuthService authService,
    IHttpClientFactory httpClientFactory)  // 新增参数
{
    _httpClient = httpClientFactory.CreateClient("VRCLSApi");
    // 不再拥有 HttpClient 的生命周期，不在 Dispose 中释放
}
```

**预期收益：**
- Socket 使用量降低 60-70%
- 连接复用提升网络响应速度
- 消除 Socket 耗尽风险

### 2.2 SettingsViewModel 资源泄漏

**问题描述：** `SettingsViewModel` 拥有 `HttpClient` 实例和多个事件订阅，但未实现 `IDisposable`。

**涉及文件：** `03.VRCLS.UI/ViewModels/SettingsViewModel.cs`

**问题代码 1 - HttpClient 未释放（第 298-301 行）：**
```csharp
private readonly HttpClient _userCenterHttpClient = new()
{
    Timeout = TimeSpan.FromSeconds(15)
};
// 类未实现 IDisposable，此 HttpClient 永远不会被释放
```

**问题代码 2 - 匿名事件处理器无法取消订阅（第 337-398 行）：**
```csharp
// 构造函数中使用匿名 lambda 订阅，无法在之后取消
_modelUpdateService.ModelsChanged += (_, __) =>
{
    // ... 处理逻辑
};
_authService.StateChanged += (_, state) =>
{
    // ... 处理逻辑
};
_steamVrService.StatusChanged += (_, status) =>
{
    // ... 处理逻辑
};
```

**修复方案：**

```csharp
public class SettingsViewModel : ObservableObject, IDisposable
{
    private readonly HttpClient _userCenterHttpClient;
    private bool _disposed;

    public SettingsViewModel(...)
    {
        _userCenterHttpClient = new() { Timeout = TimeSpan.FromSeconds(15) };

        // 使用命名方法代替匿名 lambda
        _modelUpdateService.ModelsChanged += OnModelsChanged;
        _authService.StateChanged += OnAuthStateChanged;
        _steamVrService.StatusChanged += OnSteamVrStatusChanged;
    }

    private void OnModelsChanged(object? sender, EventArgs e) { /* ... */ }
    private void OnAuthStateChanged(object? sender, BackendAuthState state) { /* ... */ }
    private void OnSteamVrStatusChanged(object? sender, string status) { /* ... */ }

    public void Dispose()
    {
        if (_disposed) return;
        _disposed = true;

        _modelUpdateService.ModelsChanged -= OnModelsChanged;
        _authService.StateChanged -= OnAuthStateChanged;
        _steamVrService.StatusChanged -= OnSteamVrStatusChanged;

        _userCenterHttpClient?.Dispose();
    }
}
```

**在 App.xaml.cs OnExit 中调用：**
```csharp
// App.xaml.cs OnExit()
var settingsVm = _serviceProvider.GetService<SettingsViewModel>();
(settingsVm as IDisposable)?.Dispose();
```

### 2.3 管道事件订阅泄漏

**问题描述：** `MainViewModel` 在重建音频管道时，旧管道的事件处理器未显式取消订阅。

**涉及文件：** `03.VRCLS.UI/ViewModels/MainViewModel.cs` 第 1264-1323 行

**问题代码：**
```csharp
private void CreateMicPipeline()
{
    // ... 签名检查 ...
    try
    {
        _micPipeline?.Dispose();  // 旧管道 Dispose，但如果 Dispose 失败...
    }
    catch (Exception ex)
    {
        _logger.Warning(ex, "Failed to dispose old mic pipeline; rebuilding.");
        // 旧的事件处理器仍然挂载！
    }
    _micPipeline = _pipelineFactory.CreatePipeline("Mic", false);
    // 新的事件处理器被添加，旧的可能仍在内存中
    _micPipeline.TextRecognized += async (_, result) => await HandleRecognitionResultAsync(result);
    // ...
}
```

**修复方案：**

```csharp
// 使用命名方法代替匿名 lambda
private async void OnMicTextRecognized(object? sender, TranscriptionResult result)
    => await HandleRecognitionResultAsync(result);
private void OnMicVolumeLevelChanged(object? sender, float v)
    => QueueUi(() => MicVolume = v, DispatcherPriority.Render);
private void OnMicSpeechStateChanged(object? sender, bool speaking)
    => QueueUi(() => IsMicSpeaking = speaking, DispatcherPriority.Render);

private void UnsubscribeFromPipeline(AudioPipelineService? pipeline, bool isMic)
{
    if (pipeline == null) return;
    if (isMic)
    {
        pipeline.TextRecognized -= OnMicTextRecognized;
        pipeline.VolumeLevelChanged -= OnMicVolumeLevelChanged;
        pipeline.SpeechStateChanged -= OnMicSpeechStateChanged;
    }
    else
    {
        pipeline.TextRecognized -= OnDesktopTextRecognized;
        pipeline.VolumeLevelChanged -= OnDesktopVolumeLevelChanged;
        pipeline.SpeechStateChanged -= OnDesktopSpeechStateChanged;
    }
}

private void CreateMicPipeline()
{
    var signature = BuildPipelineSignature("Mic", false);
    if (_micPipeline != null && string.Equals(_micPipelineSignature, signature, StringComparison.Ordinal))
        return;

    UnsubscribeFromPipeline(_micPipeline, isMic: true);  // 先取消订阅
    try { _micPipeline?.Dispose(); }
    catch (Exception ex) { _logger.Warning(ex, "Failed to dispose old mic pipeline."); }

    _micPipeline = _pipelineFactory.CreatePipeline("Mic", false);
    _micPipelineSignature = signature;

    _micPipeline.TextRecognized += OnMicTextRecognized;  // 命名方法订阅
    _micPipeline.VolumeLevelChanged += OnMicVolumeLevelChanged;
    _micPipeline.SpeechStateChanged += OnMicSpeechStateChanged;
}
```

### 2.4 TtsServiceManager 事件永不取消订阅

**问题描述：** `TtsServiceManager` 在构造函数中订阅子服务事件，但没有实现 `IDisposable`，事件处理器永远不会被清理。

**涉及文件：** `02.VRCLS.Services/Tts/TtsServiceManager.cs` 第 38-42 行

**问题代码：**
```csharp
// 构造函数中使用匿名 lambda 订阅
_localTts.SpeakCompleted += (s, e) => SpeakCompleted?.Invoke(this, e);
_localTts.SpeakError += (s, e) => SpeakError?.Invoke(this, e);
_serverTts.SpeakCompleted += (s, e) => SpeakCompleted?.Invoke(this, e);
_serverTts.SpeakError += (s, e) => SpeakError?.Invoke(this, e);
// 永远不取消订阅！SemaphoreSlim _queueGate 也不释放！
```

**修复方案：**
```csharp
public class TtsServiceManager : ITtsService, IDisposable
{
    private readonly SemaphoreSlim _queueGate = new(1, 1);
    private bool _disposed;

    // 使用命名方法
    private void OnLocalSpeakCompleted(object? s, EventArgs e) => SpeakCompleted?.Invoke(this, e);
    private void OnLocalSpeakError(object? s, string e) => SpeakError?.Invoke(this, e);
    private void OnServerSpeakCompleted(object? s, EventArgs e) => SpeakCompleted?.Invoke(this, e);
    private void OnServerSpeakError(object? s, string e) => SpeakError?.Invoke(this, e);

    public TtsServiceManager(AppConfig config, SystemSpeechTtsService localTts, ServerTtsService serverTts)
    {
        _localTts.SpeakCompleted += OnLocalSpeakCompleted;
        _localTts.SpeakError += OnLocalSpeakError;
        _serverTts.SpeakCompleted += OnServerSpeakCompleted;
        _serverTts.SpeakError += OnServerSpeakError;
    }

    public void Dispose()
    {
        if (_disposed) return;
        _disposed = true;

        _localTts.SpeakCompleted -= OnLocalSpeakCompleted;
        _localTts.SpeakError -= OnLocalSpeakError;
        _serverTts.SpeakCompleted -= OnServerSpeakCompleted;
        _serverTts.SpeakError -= OnServerSpeakError;

        _queueGate.Dispose();
    }
}
```

### 3.2 音频缓冲区频繁分配

**涉及文件：** `02.VRCLS.Services/Audio/AudioCaptureService.cs` 第 250-315 行

**问题代码：**
```csharp
private float[] ConvertBytesToFloat(byte[] bytes, int bytesRecorded, bool isFloat)
{
    int sampleCount = bytesRecorded / 4;
    float[] floatData = new float[sampleCount];  // 每次回调都新分配！（约10ms一次）
    // ...
}

private float[] ResampleAudio(float[] data, int sourceRate, int targetRate)
{
    float[] output = new float[outputLength];  // 又一次新分配！
    // ...
}

private float[] ConvertToMono(float[] stereoData)
{
    float[] monoData = new float[stereoData.Length / 2];  // 再一次新分配！
    // ...
}
```

**影响：** 每帧音频回调（约10ms）产生 3 次数组分配，约 360,000 次/小时

**修复方案：使用 ArrayPool**

```csharp
using System.Buffers;

public class AudioCaptureService : IAudioService, IDisposable
{
    // 预分配的池化缓冲区
    private float[]? _rentedConvertBuffer;
    private float[]? _rentedResampleBuffer;
    private float[]? _rentedMonoBuffer;

    private float[] ConvertBytesToFloat(byte[] bytes, int bytesRecorded, bool isFloat)
    {
        int sampleCount = isFloat ? bytesRecorded / 4 : bytesRecorded / 2;

        // 归还旧缓冲区，租用新缓冲区
        if (_rentedConvertBuffer != null)
            ArrayPool<float>.Shared.Return(_rentedConvertBuffer);
        _rentedConvertBuffer = ArrayPool<float>.Shared.Rent(sampleCount);

        if (isFloat)
        {
            Buffer.BlockCopy(bytes, 0, _rentedConvertBuffer, 0, bytesRecorded);
        }
        else
        {
            for (int i = 0; i < sampleCount; i++)
            {
                short sample = BitConverter.ToInt16(bytes, i * 2);
                _rentedConvertBuffer[i] = sample / 32768f;
            }
        }

        // 返回 Span 切片以避免暴露多余容量
        return _rentedConvertBuffer.AsSpan(0, sampleCount).ToArray();
        // 注意：最终输出仍需拷贝，但中间步骤的分配大幅减少
    }

    public void Dispose()
    {
        if (_rentedConvertBuffer != null)
            ArrayPool<float>.Shared.Return(_rentedConvertBuffer);
        if (_rentedResampleBuffer != null)
            ArrayPool<float>.Shared.Return(_rentedResampleBuffer);
        if (_rentedMonoBuffer != null)
            ArrayPool<float>.Shared.Return(_rentedMonoBuffer);
    }
}
```

**预期收益：** GC 压力降低 60-80%，音频延迟更稳定

### 4.4 EventArgs 标准化

**当前问题：** 部分事件使用原始类型，不一致

```csharp
// 不好 - 缺少上下文
event EventHandler<float[]> AudioDataAvailable;
event EventHandler<float> VolumeLevelChanged;

// 好 - 有上下文
event EventHandler<VadSpeechEventArgs> SpeechDetected;
```

**修复：统一为自定义 EventArgs**
```csharp
public sealed class AudioDataEventArgs : EventArgs
{
    public required float[] Data { get; init; }
    public int SampleRate { get; init; }
    public DateTime Timestamp { get; init; }
}

public sealed class VolumeLevelEventArgs : EventArgs
{
    public required float Level { get; init; }
}
```

同时，所有 EventArgs 应使用 `init` 属性确保不可变：
```csharp
public class VadSpeechEventArgs : EventArgs
{
    public float[] AudioData { get; init; } = Array.Empty<float>();  // init 而非 set
```

### 8.2 AudioPipelineService 状态机重构 - 消除并发核心风险

**评估结论：** 值得实施

**当前问题：** AudioPipelineService 使用 3 个 volatile bool 和 2 个 lock 表达复杂的状态转换逻辑。这些 bool 之间的组合语义是隐式的，分散在多个方法中，极易引入竞态条件。

**当前隐式状态表：**

| _recognitionEnabled | _speechInProgress | _disableAfterCurrentSpeech | 实际含义 |
|----:|----:|----:|----------|
| true | false | false | 空闲等待 |
| true | true | false | 正在识别 |
| true | true | true | 等待语音结束后禁用 |
| false | false | false | 已禁用 |
| - | - | - | 还有 Disposing、DrainTimeout 等隐含状态... |

**改进方案：显式枚举状态机**

```csharp
private enum PipelineState
{
    Idle,                    // 空闲，未捕获
    Capturing,               // 捕获中，等待语音
    SpeechDetected,          // 语音检测到，识别中
    DisablingAfterSpeech,    // 等待当前语音结束后禁用
    Disabled,                // 已禁用
    Disposing                // 正在清理
}

private int _state = (int)PipelineState.Idle;

/// <summary>
/// 原子状态转换，返回是否成功
/// </summary>
private bool TryTransition(PipelineState from, PipelineState to)
{
    var result = Interlocked.CompareExchange(ref _state, (int)to, (int)from) == (int)from;
    if (result)
        _logger.Debug("Pipeline state: {From} -> {To}", from, to);
    else
        _logger.Warning("Pipeline state transition rejected: {From} -> {To} (current: {Current})",
            from, to, (PipelineState)_state);
    return result;
}

/// <summary>
/// 获取当前状态
/// </summary>
private PipelineState CurrentState => (PipelineState)Volatile.Read(ref _state);
```

**改造后的 SetRecognitionEnabled：**
```csharp
public void SetRecognitionEnabled(bool enabled, bool drainCurrentSpeech = false)
{
    if (enabled)
    {
        // Disabled -> Idle
        TryTransition(PipelineState.Disabled, PipelineState.Idle);
    }
    else if (drainCurrentSpeech && CurrentState == PipelineState.SpeechDetected)
    {
        // SpeechDetected -> DisablingAfterSpeech
        TryTransition(PipelineState.SpeechDetected, PipelineState.DisablingAfterSpeech);
        ScheduleDrainDisableFallback();
    }
    else
    {
        // 立即禁用
        DisableRecognitionNow();
    }
}
```

### 8.4 音频管道 System.IO.Pipelines 优化 - 减少内存拷贝

**评估结论：** 值得实施（仅音频路径）

**当前：** `Channel<float[]>` 每帧一次堆分配，10ms 一帧 = 360,000 次/小时。

**改进：** `PipeReader/PipeWriter` 使用预分配内存池，零拷贝切片。

```csharp
// 替换 Channel<float[]> 为 Pipe
private readonly Pipe _audioPipe = new(new PipeOptions(
    pool: MemoryPool<byte>.Shared,
    minimumSegmentSize: 4096,      // 1024 floats = 4096 bytes
    pauseWriterThreshold: 65536,   // 16K floats 缓冲上限
    resumeWriterThreshold: 32768   // 8K floats 恢复写入
));

// 写入端（AudioCaptureService 回调）
public void WriteAudioFrame(ReadOnlySpan<float> audioData)
{
    var byteSpan = MemoryMarshal.AsBytes(audioData);
    var memory = _audioPipe.Writer.GetMemory(byteSpan.Length);
    byteSpan.CopyTo(memory.Span);
    _audioPipe.Writer.Advance(byteSpan.Length);
    _audioPipe.Writer.FlushAsync();  // 通知读取端
}

// 读取端（处理循环）
private async Task ProcessAudioPipeAsync(CancellationToken ct)
{
    var reader = _audioPipe.Reader;
    while (!ct.IsCancellationRequested)
    {
        var result = await reader.ReadAsync(ct);
        var buffer = result.Buffer;

        // 按帧大小（512 samples = 2048 bytes）消费
        while (buffer.Length >= FrameSizeBytes)
        {
            var frame = buffer.Slice(0, FrameSizeBytes);
            ProcessFrame(frame);
            buffer = buffer.Slice(FrameSizeBytes);
        }

        reader.AdvanceTo(buffer.Start, buffer.End);
    }
}
```

### 8.5 不推荐实施的模式

#### Middleware Pipeline 模式（类似 ASP.NET Core）

**结论：过度设计**

当前的事件驱动架构本身就是一种 middleware 形式。音频→VAD→识别→翻译→OSC 的流程通过事件自然串联。添加显式 middleware 管道只会增加 200+ 行抽象代码，不解决任何实际问题。

#### Actor Model（Akka.NET）

**结论：过度设计**

- Akka.NET 引入 50+MB 依赖，对桌面应用过重
- 当前 Channel\<T\> + Task 已实现 90% 的 Actor 功能
- 只有 2 个后台队列处理器，远未达到 Actor 模型的收益阈值
- **轻量替代：** 提取 `QueueProcessor<T>` 基类（~80行），统一队列处理生命周期

```csharp
// 轻量替代方案
abstract class QueueProcessor<T> : IDisposable
{
    private readonly Channel<T> _channel;
    private readonly CancellationTokenSource _cts = new();
    private Task? _processingTask;

    protected abstract Task ProcessItemAsync(T item, CancellationToken ct);

    public void Start()
    {
        _processingTask = Task.Run(async () =>
        {
            await foreach (var item in _channel.Reader.ReadAllAsync(_cts.Token))
                await ProcessItemAsync(item, _cts.Token);
        });
    }

    public void Enqueue(T item) => _channel.Writer.TryWrite(item);

    public void Dispose()
    {
        _cts.Cancel();
        _channel.Writer.Complete();
        _processingTask?.Wait(TimeSpan.FromSeconds(2));
        _cts.Dispose();
    }
}
```

#### Weak Event Pattern（WeakEventManager）

**结论：不必要**

- 当前已正确实现手动取消订阅（MainViewModel.Dispose 中 13+ 处取消）
- WeakEventManager 有约 10% 的事件触发性能开销
- 仅在动态创建/销毁订阅者的场景（如插件系统）才有价值
- 本项目的订阅者都是 Singleton 生命周期，不存在动态创建
