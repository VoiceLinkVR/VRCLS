# VRCLS 官网与状态页部署说明

## 1. 目录说明

当前仓库已经包含三部分内容：

- 官网首页：`index.html`
- 状态页前端：`status/index.html`
- 状态 API Demo：`status-api-demo/`

## 2. 官网部署到 GitHub Pages

### 2.1 推荐方式

把当前仓库内容作为一个纯静态站点仓库发布。

你有两种常见方式：

1. 用户主页仓库：`<username>.github.io`
2. 项目页仓库：`<repo-name>`，然后启用 GitHub Pages

当前代码使用的是相对路径，所以两种方式都能工作。

### 2.2 上传后需要确认的文件

至少要保证这些文件存在：

- `index.html`
- `status/index.html`
- `assets/`

### 2.3 本地预览

不要直接双击打开 HTML，建议起一个本地静态服务器：

```bash
python -m http.server 8080
```

然后访问：

- `http://localhost:8080/`
- `http://localhost:8080/status/`

## 3. 状态页接入真实后端

编辑文件：`assets/js/status-config.js`

把：

```js
apiBaseUrl: ""
```

改成：

```js
apiBaseUrl: "https://status-api.example.com"
```

状态页之后就会请求：

```text
https://status-api.example.com/api/status/public
```

如果 API 暂时不可用，会回退到示例数据。

## 4. 后端状态 API Demo 部署

### 4.1 环境要求

- Node.js 18+
- 一台可以公开访问的服务器
- 你自己的健康检查接口，或可被探测的业务地址

### 4.2 配置步骤

进入目录：

```bash
cd status-api-demo
```

复制配置文件：

```bash
cp services.example.json services.json
```

然后修改：

- `site.publicOrigin`
- `site.port`
- 每个服务的 `probeUrl`
- 每个服务的 `publicEndpoint`

### 4.3 启动

```bash
node server.js
```

默认接口：

- `GET /healthz`
- `GET /api/status/public`
- `GET /api/status/refresh`

## 5. 建议的 Nginx 反向代理

示例：

```nginx
server {
    listen 80;
    server_name status-api.example.com;

    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

正式环境建议配 HTTPS。

## 6. 建议的进程守护

### 6.1 PM2

```bash
pm2 start server.js --name vrcls-status-api
pm2 save
```

### 6.2 systemd

也可以将其做成 systemd 服务，适合 Linux 服务器长期运行。

## 7. 生产环境建议

- 将 `publicOrigin` 改成你实际的 GitHub Pages 域名
- 用真实健康检查接口替换示例地址
- 将事件记录落库，不要只保存在内存中
- 增加计划维护公告接口
- 如需高可靠，状态 API 自己也应被另一个监控源检查

## 8. 推荐上线顺序

1. 先在本地预览官网和状态页
2. 再启动 `status-api-demo`
3. 把 `assets/js/status-config.js` 指向真实 API
4. 确认 CORS 正常
5. 最后上传静态站到 GitHub Pages

## 9. 当前 Demo 的定位

这一版不是最终官网，而是：

- 设计方向确认稿
- 可运行的第一版代码
- 可继续往正式版本迭代的基础骨架
